- **Review date:** 2026-08-25

This is the canonical #150 inventory. It audits the programmable semantic
surface above raw call grammar; it does not implement the gaps it records.
The #61 closure and PR #131 established a bounded programmable-document
foundation, not complete v2.5.1 compatibility. The current matrix therefore
classifies every row against the upstream observable contract instead of
promoting an existing Arkst implementation merely because the #61 checklist
passed.

## Method and evidence boundary

The audit used only permitted clean-room evidence:

1. the public v2.5.1 wiki/API documentation;
2. public v2.5.1 source/API declarations pinned to the full commit above;
3. independently authored black-box probes against the installed official
   `quarkdown version 2.5.1` release binary;
4. current Arkst implementation, tests, fixtures, ADRs, and compatibility
   documents; and
5. live issue/PR history for ownership and prior evidence.

No Quarkdown source, internal test, or fixture was copied or translated. The
black-box probes were small documents authored for this audit and compared
observable output and failure effects. Upstream source links below are
provenance and behavioral evidence, not implementation instructions.

The primary status is exactly one #147 vocabulary value per inventory row:

`SUPPORTED_END_TO_END`, `SUPPORTED_SEMANTICS`, `PARSED_ONLY`, `PARTIAL`,
`UNSUPPORTED`, `DEFERRED`, `BLOCKED`, `NOT_APPLICABLE`, or `UNKNOWN`.

`PARTIAL` is used when a bounded semantic slice is evidenced but the public
surface or observable contract is broader. `SUPPORTED_SEMANTICS` is reserved
for semantic behavior whose runtime contract is evidenced independently of a
complete rendered-document claim. No #150 row is promoted to
`SUPPORTED_END_TO_END` by this audit.

## Pipeline and ownership boundary

The upstream call pipeline is represented by the pinned
[`FunctionCallRefiner.kt`](https://github.com/iamgio/quarkdown/blob/107ec3a9482f10d6f90d7580f8409b46a719d18e/quarkdown-core/src/main/kotlin/com/quarkdown/core/parser/FunctionCallRefiner.kt),
[`FunctionCallNodeExpander.kt`](https://github.com/iamgio/quarkdown/blob/107ec3a9482f10d6f90d7580f8409b46a719d18e/quarkdown-core/src/main/kotlin/com/quarkdown/core/function/call/FunctionCallNodeExpander.kt),
and [`NodeOutputValueVisitor.kt`](https://github.com/iamgio/quarkdown/blob/107ec3a9482f10d6f90d7580f8409b46a719d18e/quarkdown-core/src/main/kotlin/com/quarkdown/core/function/value/output/node/NodeOutputValueVisitor.kt).
Arkst keeps the corresponding semantic ownership in the single
`arkst-engine` evaluator: AST-to-IR conversion, evaluation, builtins,
conversion, normalization, `CallOutcome`, callable capture, and source-backed
diagnostics. `arkst-core` remains the composition/facade layer. The
backend-neutral `IrDocument` and typed `IrValue`/`IrComponent` boundary do not
acquire evaluator-specific or Typst-specific semantics in this audit.

The #149 value/binding/conversion audit is a referenced ownership boundary,
not a second #150 inventory. Where a call's parameter behavior affects
programmable semantics, the flow is recorded as:

`ordered call candidates -> #165 binding policy -> #149 target-driven conversion ->
evaluator scope and owner write-back`.

Document-state mutation is also kept separate. The shared evaluator-owned
`DocumentState` handle is noted only where it affects scope; metadata getter,
setter, append/replace, serde, and frontmatter behavior belong to [#152](https://github.com/luceat-lux-vestra/scribium/issues/152).

## Status and implementation boundary

The current canonical status is conservative: the callable, scope, argument,
`.let`, evaluation-order, chain, conditional, iteration, optionality/callback,
collection, precedence, failure, diagnostic, and bounded extension/super groups
are `PARTIAL`; `.node` remains `UNSUPPORTED`; document-state separation is
`NOT_APPLICABLE` to this audit.
No row is `SUPPORTED_END_TO_END`. The #169 implementation strengthens the
extension/super row only to `PARTIAL`: it resolves visible source-defined
callables and regular scalar builtins through the existing evaluator and shared
binder, preserves target parameter names, supports conditional delegation and
ordered extension chains, and exposes `.super` only in the active extension
invocation. Ordinary helper calls inherit the active dynamic extension context,
nested extensions replace and then restore it, and condition lambdas do not
receive the injected `.super`. It does not claim specialized layout/resource/document-state/native
owners, renderer compatibility, or upstream partial-effects parity.

The implementation keeps extension links and invocation bodies evaluator-owned;
it assigns monotonic evaluator-local link identities, validates weak owners,
and retires overlays reachable from a replaced function root through the
existing savepoint journal. It adds no extension IR, backend type, environment
snapshot, or second evaluator. The contextual frontend metadata needed to identify an extension
body and `where` lambda is covered by the existing parser path. Invocation
savepoints use the existing #167 transaction journal, including field-specific
`DocumentState` undo and function/link writeback. Independent evidence is in
`crates/arkst-core/tests/quarkdown_function_extension.rs` and
`crates/arkst-markdown/src/parser.rs`.

Remaining work includes the broader callable/native target matrix, complete
upstream failure-effect equivalence, end-to-end output evidence, and any
specialized target owners. Implementation ordering for those surfaces follows
the dependency-aware #156 reconciliation; #157–#167 remain separate adjacent
workstreams.
