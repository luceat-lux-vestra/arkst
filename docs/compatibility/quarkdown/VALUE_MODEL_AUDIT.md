## Status vocabulary

`SUPPORTED_END_TO_END` requires frontend, semantic, and appropriate backend or
document-observable evidence. `SUPPORTED_SEMANTICS` requires evaluator/IR
evidence but does not claim rendering parity. `PARSED_ONLY` is frontend
evidence without semantic support. `PARTIAL` identifies a bounded supported
slice with an exact remaining gap. `UNSUPPORTED`, `DEFERRED`, `BLOCKED`, and
`UNKNOWN` are not compatibility claims. `NOT_APPLICABLE` means the reviewed
v2.5.1 contract does not expose that surface as a general value/binding
category.

## Binding and conversion conclusions

The ordered `IrCallArgument` view is a lightweight sequence of projection
indexes and source spans. It preserves mixed argument order without owning a
second `IrValue` tree; the existing positional and named projections remain
the value owners for evaluator adapters.

### Binding is semantic, not parser grammar

The pinned upstream binder receives an ordered argument sequence, records that
named arguments have begun, and rejects an unnamed argument after a named one
as a binding error. Arkst's grammar/frontend and IR now preserve that
sequence, including positional-after-named transitions, without parser
`E2001` or a pre-binder handoff rejection. The engine-owned `invocation_binder`
is now the single semantic owner for source-order checks, exact names and
explicit aliases, duplicate/collision/excess checks, required and optional
slots, defaults, and target-specific body policy. Its source-backed errors
retain the offending argument and conflict spans, including the positional
after named primary/secondary pair.

The shared binder is used through metadata adapters by regular native
signatures, bespoke native consumers, source-defined functions, and ordinary
callback/lambda invocation. Ordered candidates are validated before evaluation
where that is required to prevent invalid calls from executing; evaluated
candidates are then converted by the selected target. The implementation is a
bounded #165 semantic slice, with #166 now providing the shared dynamic/content
target boundary and raw-body channel described below. #167 now provides the
shared conversion-diagnostic and invocation atomicity contract for the audited
consumers; complete upstream consumer coverage remains outside this slice.

### Conversion is target-driven and closed

The audit found no evidence for generalized coercion. The actionable accepted
families are:

| Source value | Target | Result at the reviewed boundary |
|---|---|---|
| typed Number/Boolean/Range/Size/Color/closed Enum | same target/domain | Accepted by identity |
| dynamic String/Identifier | Number/Integer/Boolean/Range/Size/Color/closed Enum | Conditionally accepted by the target parser and closed table |
| static String | Number/Integer/Boolean/Range/Size/Color/closed Enum | Rejected in the bounded origin-aware path |
| bounded scalar | String | Accepted by the bounded scalar string adapter |
| None | nullable/optional target | Accepted only where the target is nullable or optional |
| Content/Collection/Pair/Dictionary/Callable/Component | unrelated scalar/domain target | Rejected; no implicit stringification |
| Markdown list/dictionary/body | iterable/dictionary/content target | Accepted only by its explicit context-sensitive adapter |

This table is intentionally not a claim that every upstream target has been
implemented. It is a negative boundary as well as a positive matrix: a value's
display form does not establish a conversion contract.

### Nested evaluation and mutation

The current evaluator's intended order is:

```text
callee resolution
  -> obtain the source-ordered invocation candidates
  -> select target slots and validate binding
  -> evaluate non-body candidates, left to right
  -> origin-aware target conversion
  -> apply omission/default/body policy
  -> child scope / parameter installation
  -> lazy body evaluation when selected
  -> builtin execution
  -> document-state commit
  -> output materialization
```

Independent tests establish this order for the bounded native, callable,
collection, and document-state paths. They also establish rollback for the
reviewed stateful consumers. The evaluator-private invocation checkpoint is a
savepoint at each invocation boundary: failed or unresolved nested work is
undone even when the enclosing invocation preserves that value and succeeds,
while successful nested work merges into the outer savepoint. First-write
metadata uses each ephemeral scope's savepoint floor: bindings created and
discarded at that scope's own boundary are not journaled, but writes from a
deeper savepoint to a still-live owner remain rollbackable. Document-state
undo is field-specific; append-only author state records a prior length and
replaceable fields move their prior value into the undo entry rather than
cloning the whole state. Preservation evaluation also runs in a disposable
savepoint so retained unresolved syntax cannot republish failed side effects.
The matrix remains `PARTIAL` only because the complete upstream consumer
inventory is not implemented.
