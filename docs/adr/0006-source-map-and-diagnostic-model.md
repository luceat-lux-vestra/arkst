# ADR-0006: Source Map and Diagnostic Model

- **Status:** Accepted
- **Date:** 2026-08-02
- **Owners:** Scribium maintainers
- **Related issues:** #1, #8

## Context

Scribium produces generated Typst code and must map Typst compilation errors
back to original source positions. Without source maps, users debug generated
code they never wrote.

## Decision Drivers

- Typst errors must show original `.qd`/`.md` location, not generated `.typ`
- Generated code must be human-readable for debugging
- Source map must survive lowering transformations

## Considered Options

### Option 1: Line-based offset map (chosen for M1)

Record for each generated line: `(source_id, source_line, source_column)`.
Mapping is O(1) lookup by generated line number. Simple, sufficient for M1.

### Option 2: Span-based map with overlapping ranges

Full byte-level mapping with overlapping ranges (one generated byte → multiple
source spans possible for synthesized code). More precise but more complex.

## Decision

Start with line-based offset map for M1. Each generated line records its
origin. Upgrade to span-based mapping before v0.1.

## Consequences

### Positive

- Trivial to implement for M1
- Typst diagnostics (which are line-based) map cleanly
- No complex data structures needed

### Negative

- Cannot distinguish multiple sources within one line
- Synthesized code (e.g., wrapping boilerplate) has imprecise mapping

### Risks

- Late upgrade to span-based map may miss edge cases
- Mitigation: design the `SourceMap` type to support both modes from day one

## Diagnostic model

```
Diagnostic {
    code: String,           // stable code like "E0123"
    severity: Severity,     // Error | Warning | Hint
    message: String,
    primary_span: Span,     // original source location
    secondary_spans: Vec<Span>,
    hints: Vec<String>,
}
```
